## 中文

GameCase 1.0.18 改善游戏库与导入效率，并在操作失败时保护已有数据。

- 封面使用能够识别文件版本的缓存，总开销限制为 48 MiB，图片数量限制为 32 张。保留原始像素尺寸和封面来源优先级。收到内存警告、主动更换封面或启动游戏时清理缓存。
- 文件复制进度约每秒更新 10 次，同时保留 4 MiB 缓冲区、每个数据块的取消检查、完整写入及最终同步。多文件导入也限制汇总进度的界面刷新频率。
- Mod 和 DLC 文件夹导入复用一次经过检查的目录快照来获取文件列表和大小。存档导入及备份会报告目录枚举错误，保留空目录，并拒绝不支持的符号链接，避免静默遗漏。只有完整完成的存档备份才会使用最终名称。
- 游戏更新先在暂存区完成准备和签名，再替换原应用。准备失败时保留已安装版本；提交失败时使用既有回滚机制。Inbox 导入失败或取消时保留源 IPA。
- Mod 回滚时保留无法恢复的原文件，并报告可用于恢复的位置。
- 偏好设置与 env 写入保留原 inode 以维持兼容性，并在同步写入通过验证前保留恢复数据。下次访问时会恢复尚未处理的恢复文件。

验证覆盖实际使用的 Swift 存储、复制和缓存工具，包括模拟部分写入和回滚失败、偏好写入中断、目录枚举失败、备份完成检查、应用准备及提交失败、缓存失效，以及逐字节复制一致性。既有金手指、压缩包和打包回归测试继续启用。

这些改动针对 GameCase 的游戏库浏览、导入与失败恢复，不改变游戏 IPA 的渲染器、着色器或金手指虚拟机，也不声称游戏帧率或设备整体速度提升的百分比。

## English

GameCase 1.0.18 improves library and import efficiency and protects existing data when operations fail.

- Cover images use a file-version-aware cache with a 48 MiB cost limit and a 32-image count limit. Original pixel dimensions and cover-source priority are preserved. Memory warnings, explicit cover changes and game launches clear the cache.
- File copies report progress at roughly 10 updates per second while retaining the 4 MiB buffer, per-chunk cancellation checks, complete writes and final synchronization. Multi-file imports also throttle their aggregate UI updates.
- Mod and DLC folder imports reuse one checked directory snapshot for file lists and sizes. Save imports and backups propagate enumeration errors, preserve empty directories, and refuse unsupported symbolic links instead of silently omitting them. Only complete save backups receive their final name.
- Game updates are prepared and signed in staging before the previous app is replaced. Failed preparation preserves the installed version; failed commit uses the existing rollback mechanism. Failed or cancelled Inbox imports retain their source IPA.
- Mod rollback retains originals that cannot be restored and reports their recovery location.
- Preference and env writes retain their existing inode for compatibility and keep recovery bytes until synchronized writes are verified. A pending recovery file is restored on the next access.

Validation covers the production Swift storage/copy/cache utilities, simulated partial writes and rollback failures, interrupted preference writes, directory enumeration failures, backup completion, app preparation/commit failures, cache invalidation and byte-for-byte copying. Existing cheat, archive and packaging regressions remain enabled.

These changes target GameCase library browsing, imports and failure recovery. They do not change the game IPA's renderer, shaders or cheat VM, and no game-FPS or device-level speedup percentage is claimed.
